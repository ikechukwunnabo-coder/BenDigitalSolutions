An issue is a problem that has already occurred. A risk is a problem that may occur
(see the risk register, to be created in Phase 1).

## Severity scale

| Level | Definition | Response target |
| --- | --- | --- |
| Critical | Blocks delivery, or causes data loss or security exposure | Same session; escalate immediately |
| High | Blocks a milestone or a key feature | Within 1 working session |
| Medium | Degrades quality or schedule but work can continue | Within the current sprint |
| Low | Cosmetic or minor inconvenience | Backlog; next appropriate sprint |

## Rules

- Record the issue when it is found, not after it is fixed.
- Never close an issue without evidence of resolution.
- Critical issues are reported in the weekly status report and to the project owner.
