PART B: PROJECT MANAGEMENT PLAN

### 15. Project Management Approach
The project will use a hybrid methodology combining formal project management controls with Agile delivery practices.
Formal project management will guide:

- Project initiation.
- Scope and budget approval.
- Risk management.
- Stakeholder communication.
- Milestone management.
- Change control.
- Quality assurance.
- Project closure.
Agile practices will guide:

- Feature prioritisation.
- Sprint planning.
- Incremental development.
- Iterative testing.
- Continuous feedback.
- Retrospectives and improvement.

### 16. Project Lifecycle
The project will follow these stages:
**Stage 1 — Initiation**

- Define the business need.
- Identify project objectives.
- Establish the project charter.
- Identify stakeholders.
- Confirm project constraints.
**Stage 2 — Planning**

- Define project scope.
- Develop the Work Breakdown Structure.
- Prepare the schedule.
- Estimate project costs.
- Identify and assess risks.
- Develop the communication plan.
- Define quality and acceptance criteria.
**Stage 3 — Execution**

- Design the system architecture.
- Establish the development environment.
- Develop the backend.
- Develop the frontend.
- Implement administrative functionality.
- Integrate the system components.
**Stage 4 — Monitoring and Controlling**

- Monitor task completion.
- Compare actual progress against the baseline.
- Review risks and issues.
- Control scope changes.
- Track budget and quality.
- Produce weekly status reports.
**Stage 5 — Closure**

- Complete final testing.
- Obtain acceptance of deliverables.
- Deploy the platform.
- Document lessons learned.
- Complete the closure report.
- Archive project documentation.

### 18. Project Schedule and Sprint Structure
The proposed project duration is 12 weeks, with approximately 10–15 working hours available weekly.
The development work will be organised into two-week iterations where practical.

| Sprint | Focus | Expected Output |
| --- | --- | --- |
| Sprint 0 | Initiation and planning | Approved baseline and architecture plan |
| Sprint 1 | Technical foundation | Django, React and database foundations |
| Sprint 2 | Public website | Core website pages and responsive layouts |
| Sprint 3 | Business management | Lead, customer and service management |
| Sprint 4 | Administrative platform | Project tracking and dashboard |
| Sprint 5 | Integration and testing | Tested and accepted MVP |
| Release | Deployment and closure | Production release and final report |

The detailed schedule will be maintained separately, including task owners, dependencies, start dates, end dates and actual completion status.

### 19. Scope Management
All project work must align with the approved MVP scope.
Any proposed additional functionality must be evaluated based on:

- Business value.
- Development effort.
- Financial impact.
- Schedule impact.
- Security implications.
- Effect on existing requirements.
Changes that materially affect scope, budget, timeline or acceptance criteria must be documented in a Change Request Log and formally approved by the Project Manager.

### 20. Cost Management
The Project Manager will:

- Establish an approved project budget.
- Record estimated and actual expenditure.
- Monitor commitments and remaining funds.
- Document budget variances.
- Review additional expenditure before purchase.
- Maintain receipts and payment evidence.
Budget performance will be reviewed weekly.

### 21. Risk Management
Risks will be identified, assessed, monitored and addressed throughout the project.
Each risk will be assessed using:

- Probability: Low, Medium or High.
- Impact: Low, Medium or High.
- Risk priority.
- Mitigation action.
- Contingency response.
- Responsible owner.
- Current status.
The Risk Register will be reviewed weekly and whenever a significant project change occurs.

### 22. Quality Management
Quality will be built into every development iteration.
Quality assurance activities will include:

- Requirements validation.
- Code review.
- Database integrity checks.
- API testing.
- Frontend usability testing.
- Responsive design testing.
- Authentication and authorisation checks.
- Input validation.
- Error handling.
- Security checks.
- Performance testing.
- User acceptance testing.
No critical feature will be considered complete simply because the code has been written. It must satisfy its acceptance criteria and pass the relevant tests.
AI-generated code must be reviewed, tested and understood before being accepted into the project.

### 23. Communication Management
Communication will be maintained through a structured reporting process.

| Communication | Frequency | Method |
| --- | --- | --- |
| Personal project review | Daily or per work session | Project task board |
| Progress review | Weekly | Project status report |
| Sprint planning | Every two weeks | Sprint backlog |
| Sprint review | Every two weeks | Working software demonstration |
| Risk review | Weekly | Risk register |
| Budget review | Weekly | Budget tracker |
| Project closure review | End of project | Closure report |

The Project Manager will maintain written records of major decisions, changes and approvals.

### 24. Resource Management
The project is designed as a solo-led initiative.
The Project Manager will perform the following responsibilities:

- Project planning and coordination.
- Product ownership and prioritisation.
- Requirements analysis.
- Software development.
- Technical architecture decisions.
- Quality assurance.
- Risk and budget management.
- Documentation and reporting.
AI assistance will be used for technical research, coding support, testing suggestions, documentation, troubleshooting and review.
The Project Manager remains accountable for all decisions and deliverables.

### 25. Change Management
Changes will follow a controlled process:

- Identify the requested change.
- Document its business justification.
- Assess impact on scope, time, cost, quality and risk.
- Approve, defer or reject the change.
- Update the relevant project documents.
- Implement the approved change.
- Verify and record the outcome.
Unapproved changes must not be treated as part of the project baseline.

### 27. Project Closure and Evaluation
At project completion, the Project Manager will conduct a formal review.
The closure process will include:

- Confirmation of deliverable completion.
- Acceptance testing results.
- Deployment verification.
- Budget reconciliation.
- Documentation review.
- Lessons learned.
- Outstanding issues and recommendations.
- Final project performance assessment.
The final closure report will serve as a central document in the Project Manager's professional portfolio.

### 28. Project Management Portfolio Evidence
The following evidence will be preserved:

- Approved project charter.
- Project management plan.
- Work Breakdown Structure.
- Gantt chart or project schedule.
- Sprint boards and task records.
- Budget and expenditure tracker.
- Risk register.
- Stakeholder and communication records.
- Weekly status reports.
- Change request records.
- System architecture documents.
- Development and testing evidence.
- Deployment evidence.
- Project closure report.
- Final project case study.
Confidential information, passwords, API keys and sensitive customer data must never be included in the public portfolio.
